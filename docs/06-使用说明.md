> 版本：v0.2（2026-11-26）
> 适用范围：演示台、管理端、LoRa 网关固件、网关模拟器
> 项目目录：`Desktop/qoder-cup-2026`

---

## 0. 三十秒了解

ResQNet 是一个"断网灾区也能互通"的应急信息层：

- **演示台**：浏览器里跑协议仿真，看 SOS/文字/语音如何多跳到达指挥车
- **管理端**：真实台账、事件处置、消息下发，可接真实 LoRa 网关
- **网关固件**：ESP32-S3 + SX1262，把 LoRa 网络桥接到管理端（WebSocket），同时给手机开 BLE
- **模拟器**：没有硬件时，模拟一个网关把数据喂给管理端

三条入口：

| 入口 | 地址 | 用途 |
|---|---|---|
| 演示台 | https://resqnet-t2bci1hjbry.qoder.zone | 给评委/观众看协议与态势 |
| 管理端 | https://resqnet-console-t2bci1hjbry.qoder.zone | 真实台账与事件处置 |
| 仓库 | https://github.com/1345463/resqnet | 源码、固件、文档 |

## 1. 演示台（app/）

### 1.1 打开

直接访问 https://resqnet-t2bci1hjbry.qoder.zone 。

想让它自动跑一段：在链接后加 `?auto=1`，1.5 秒后最远节点会自动发 SOS，6.5 秒后补一条文字。

### 1.2 界面

- **左栏**：演练场景（城区 / 山地 / 震后）、节点列表、主中继显示
- **中间**：态势地图。圆点是终端，方块是指挥车，青色箭头是当前主中继
- **右栏**：指标卡、语音传输进度、传输日志、演示步骤
- **底部**：当前节点、SOS 按钮、文字输入、录音/模拟语音

地图说明：

- 点击节点选中；点击"断开"可模拟设备故障
- 外圈弧线是电量
- 链路颜色：绿=强、黄=中、红=弱
- 数据包：红=SOS、青=文字/语音、灰=位置

### 1.3 推荐演示脚本（3 分钟）

1. 选"城区搜救"，点一个居民节点
2. 点 **SOS 求救**：看红色包多跳到达指挥车，日志出现"回执"
3. 在节点列表里把"中继-01"点"断开"：观察路径绕行、主中继切换
4. 切到"山地失联"：说明地形遮挡如何影响链路
5. 发一条文字或点"模拟语音"：展示分片进度与送达时延

### 1.4 语音

- **按住说话**：需要浏览器麦克风权限，停止后自动发送
- **模拟语音**：无需麦克风，生成一段提示音走完整个分片流程
- 语音以"语音消息"形式传输（分片→重组→播放），不是实时通话

## 2. 管理端（console/）

### 2.1 打开

- 公网版：https://resqnet-console-t2bci1hjbry.qoder.zone
- 看示例数据：链接后加 `?demo=1`（只在台账为空时生效）
- 本地版（接真实网关必须用这个）：
  ```bash
  cd console
  npm install
  npm run dev      # 默认 5173 端口
  ```

> **为什么接网关要用本地版**：公网是 HTTPS，浏览器不允许它连接局域网 `ws://`（混合内容拦截）。本地 `http://localhost` 没有这个限制。

### 2.2 界面

- **顶栏**：时间、网关状态、常规/应急模式
- **左栏**：节点台账（搜索、按角色筛选、定位、删除手工节点）
- **中间**：高德底图（已做 WGS84→GCJ-02 纠偏）、事件脉冲、节点标记
- **右栏**：事件 / 消息 / 设置 三个页签

地图操作：

- 拖拽平移
- **Ctrl + 滚轮**缩放（普通滚轮滚动页面，避免误触）
- 右上角 `+ / −` 缩放
- 点节点选中；"定位"把地图移到该点

### 2.3 接网关

1. 打开本地管理端
2. 右侧 → 设置 → 网关 WebSocket 地址，填：
   - 真实硬件：`ws://<网关IP>:81/`
   - 模拟器：`ws://127.0.0.1:8081/`
3. 令牌/频道可留空（固件 v0.1 暂未校验）
4. 顶栏出现"网关在线"即成功

连接后：

- 网关上报的位置 → 自动出现在台账与地图
- 网关上报的 SOS → 自动生成"紧急"事件
- 管理端发消息 → 经网关下发到 LoRa

### 2.4 事件处置

- SOS 事件默认"待响应"
- 点 **响应** → "处置中"；点 **关闭** → "已关闭"
- 点 **定位** → 地图飞到事件位置并选中节点

### 2.5 消息

- 顶部选择目标（全部节点 / 某个节点）
- 输入文字回车或点"发送"
- 网关在线：状态"已发往网关"；离线：状态"失败"
- 收到的文字显示在列表，带节点名与时间

### 2.6 应急模式（重要）

打开"设置 → 应急模式"，填写：

| 字段 | 说明 |
|---|---|
| 呼号 | 你的业余电台呼号 |
| 授权/报备编号 | 属地无管机构回执编号 |
| 报备机构 | 如 XX 市无线电管理处 |
| 使用频段 | 如 430-440MHz |
| 发射功率 | 实际使用功率（W） |
| 报备时间 | 启用时间 |

开启后顶部常驻一条黄色横幅，提醒合规要素。

> 依据《无线电管理条例》第三十七条：紧急情况可临时设台，但须及时报告，事后关闭。应急模式只是登记提醒，不替代报备。

### 2.7 数据管理

- 所有台账/事件/消息存在浏览器 localStorage（键 `resqnet.console.v1`）
- 换浏览器或清缓存会丢，重要数据先导出
- 设置 → 数据 → **导出 JSON（复制）**；粘贴到文本框可**导入 JSON**
- "加载演示数据"会覆盖当前节点列表，正式使用前先导出

### 2.8 手工录入节点

设置 → 新增节点：名称、呼号、角色、经纬度 → 添加。适合没有网关时先建台账。

## 3. 网关固件（firmware/gateway/）

### 3.1 准备

- Heltec WiFi LoRa 32 V3（ESP32-S3 + SX1262）
- 433 MHz 天线（不要加功放）
- USB-C 线、电脑装好 PlatformIO

### 3.2 配置

编辑 `src/config.h`：

```cpp
#define WIFI_SSID "你的WiFi"
#define WIFI_PASS "密码"
#define GW_NODE_ID "gw1"
#define GW_NAME "LoRa网关"
```

- WiFi 连不上会自动开热点 **ResQNet-GW / resqnet123**，IP `192.168.4.1`
- 默认 LoRa：433.175 MHz、SF9、BW125、8 dBm（微功率）
- 建站使用 430–440 MHz 更大功率时，先确认电台执照与当地协调

### 3.3 编译烧录

```bash
cd firmware/gateway
pio run -t upload
pio device monitor
```

正常日志：

```
[WiFi] STA IP: 192.168.1.23
[LoRa] ready 433.175 MHz SF9 BW125
[BLE] advertising as ResQNet-GW
[WS] listening on port 81
```

> 固件尚未在实机编译验证（开发环境无 PlatformIO/开发板）。首次烧录如报库版本错误，按 PlatformIO 提示升级 `RadioLib` / `NimBLE-Arduino` 后重试。

### 3.4 连接管理端

1. 电脑与网关同一网络（或连网关热点）
2. 本地启动管理端
3. 设置里填 `ws://<网关IP>:81/`
4. 顶部"网关在线"

### 3.5 手机 BLE 联调

- 手机装 **nRF Connect**
- 扫描并连接 `ResQNet-GW`
- 找到服务 `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- 向 RX `6E400002-...` 写入 JSON：

```json
{"k":"p","n":"队员-07","x":30.66,"y":104.06,"b":72}
{"k":"t","n":"队员-07","m":"已到达东岸"}
{"k":"s","n":"队员-07","x":30.66,"y":104.06,"m":"腿部受伤"}
```

- 管理端应出现节点/消息/事件；TX `6E400003-...` 会收到网关通知

### 3.6 管理端下发指令

管理端"消息"里发给节点或全部 → 串口打印 TX → LoRa 节点收到；网关回 `ack`。

### 3.7 接线（外置 SX1262）

| 信号 | GPIO |
|---|---|
| NSS | 8 |
| SCK | 9 |
| MOSI | 10 |
| MISO | 11 |
| RST | 12 |
| BUSY | 13 |
| DIO1 | 14 |

## 4. 网关模拟器（tools/gw-sim/）

没有硬件时用它把管理端跑通：

```bash
node tools/gw-sim/server.mjs
```

- 监听 `ws://127.0.0.1:8081/`
- 每 4 秒推送 4 个节点的位置
- 6 秒后发一条 SOS，9 秒后发一条文字
- 管理端下发的指令会打印 `[sim] downlink -> ...` 并回 `ack`

管理端设置里填 `ws://127.0.0.1:8081/` 即可。

> 模拟器无依赖，不需要 npm install。

## 5. 现场部署流程（推荐顺序）

1. **建台账**：管理端录入队伍与呼号，或直接用网关上报
2. **架网关**：高处/车载，插电、连网（或热点）
3. **开应急模式**：填呼号、报备、频段、功率
4. **发终端**：手机装 nRF Connect 或后续现场 App，配对 `ResQNet-GW`
5. **验链路**：让一个终端发位置 → 管理端出现；发文字 → 管理端收到
6. **测覆盖**：两人拉开距离，记录 RSSI 与丢包
7. **收队**：关闭临时台站，补全报备记录

## 6. 协议速查

### 6.1 LoRa 帧（≤200 B）

```json
{"v":1,"k":"t","f":"u1","to":"*","q":12,"ttl":4,
 "n":"队员-01","c":"BG8XXX","r":"phone",
 "x":30.66,"y":104.06,"b":80,"m":"两人受困","ts":1732580000000}
```

`k`：`t` 文字 / `p` 位置 / `s` 求救。

### 6.2 管理端 WebSocket

网关是服务端，管理端是客户端。

上行：`hello` / `position` / `text` / `sos` / `offline`
下行：`command`（`to` 为节点 ID 或 `*`）
回执：`ack`

完整字段见管理端「设置 → 网关接入协议」。

## 7. 常见问题

**Q：管理端显示网关异常？**
- 确认地址是 `ws://` 不是 `http://`
- 确认端口 81 没被防火墙拦
- 公网 HTTPS 页面连不了局域网 `ws://`，换本地管理端
- 手机热点下确认电脑与网关同网段

**Q：地图空白/灰块？**
- 高德瓦片需要联网；离线时仍显示节点与坐标网格
- 检查公司网络是否拦截 `is.autonavi.com`

**Q：节点位置偏几百米？**
- 管理端已做 WGS84→GCJ-02；如果终端上报的是 GCJ-02，会二次偏移，需统一坐标系

**Q：BLE 写入没反应？**
- 确认连的是 `ResQNet-GW`
- 先协商 MTU（固件设 247，手机端 requestMtu）
- 写入的是 RX 特征（`...0002`），不是 TX

**Q：LoRa 发不出去？**
- 串口看 `[LoRa] init failed`：检查天线、供电、引脚
- 帧超 200 B 会被拒，文本控制在 ~120 字节
- 两台设备参数（频率/SF/BW/同步字）必须一致

**Q：npm install 失败？**
- 本机有代理证书问题时：`NODE_OPTIONS=--use-system-ca npm install`
- 作用域包 404：先 `node tools/npm-registry-proxy.js`，把 `.npmrc` 指向 `http://127.0.0.1:4873/`

**Q：演示台/管理端数据会丢吗？**
- 演示台是内存仿真，刷新即重置
- 管理端存 localStorage，清缓存/换浏览器会丢，先导出

## 8. 合规与安全

- 433 MHz 微功率限值 10 mW（e.r.p），不得加功放、改天线
- 470–510 MHz 限定为民用计量等用途，**不得用于组网**
- 430–440 MHz 需业余电台执照；B 类 30 MHz 以上 ≤25 W
- 应急临时设台按条例第 37 条报告并在事后关闭
- 当前固件无加密、无鉴权，仅用于演示；正式使用前必须加密钥与访问控制
- 不要在机场、射电天文台等敏感区域发射
