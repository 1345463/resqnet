# ResQNet 协议规范 v0.1

> 目标：一套协议，多端（Web/Android/iOS/桌面/嵌入式）复用；换射频只换 adapter。
> 编码：CBOR。所有整数小端。时间：HLC（混合逻辑时钟）。

---

## 1. 术语

| 术语 | 含义 |
|---|---|
| Node | 一个具备身份密钥的终端/中继 |
| Envelope | 线上传输的不可变消息信封（含签名/校验） |
| Channel | 逻辑频道（公共广播 / 队伍加密频道 / 私聊） |
| HLC | 混合逻辑时钟，物理时间 + 逻辑计数，抗时钟漂移 |
| ETX | 期望传输次数，链路质量度量 |
| Relay | 被选中的转发节点 |

---

## 2. 帧格式

```
+--------+---------+------+-------+--------+-------+-----+-------+-------+-------+------+---------+--------+
| MAGIC  | VERSION | TYPE | FLAGS | MSG_ID |  TTL  | HOP |  SRC  |  DST  |  HLC  | LEN  | PAYLOAD |  AUTH  |
|  2 B   |   1 B   | 1 B  |  1 B  |  8 B   |  1 B  | 1 B |  4 B  |  4 B  |  6 B  | 2 B  | 0..N B  | 16/64B |
+--------+---------+------+-------+--------+-------+-----+-------+-------+-------+------+---------+--------+
```

- `MAGIC` = `0x52 0x51`（"RQ"）
- `VERSION` = `0x01`
- `MSG_ID` = 发送方单调序号（8 B），与 SRC 组合全局唯一
- `SRC/DST` = 节点短 ID（公钥 BLAKE2b 前 4 B）；`DST=0xFFFFFFFF` 表示广播
- `HLC` = 48 bit（32 bit 秒 + 16 bit 计数）
- `AUTH` = 默认 16 B 截断 HMAC（群组密钥）；身份类消息用 64 B Ed25519 签名

> **尺寸预算**：LoRa 单帧目标 ≤ 200 B → 头部 27 B + AUTH 16 B = 43 B，payload ≤ 157 B。BLE 目标 ≤ 180 B，WiFi 可到 1200 B。

---

## 3. 消息类型

| TYPE | 名称 | 方向 | 优先级 | 说明 |
|---|---|---|---|---|
| 0x01 | BEACON | 广播 | 3 | 邻居发现：能力、位置、电量、负载 |
| 0x02 | SOS | 广播 | 0 | 求救，含位置/人数/伤情/电量 |
| 0x03 | TEXT | 单播/广播 | 2 | 文本（CBOR string，UTF-8） |
| 0x04 | POS | 广播/单播 | 3 | 单个位置 |
| 0x05 | POS_BATCH | 广播 | 4 | 位置批量（降频聚合） |
| 0x06 | VOICE_META | 单播/广播 | 2 | 语音元数据（时长/编码/分片数） |
| 0x07 | VOICE_CHUNK | 单播/广播 | 2 | 语音分片 |
| 0x08 | ACK | 单播 | 1 | 端到端回执（含被确认 MSG_ID） |
| 0x09 | RREQ | 广播 | 1 | 路由请求 |
| 0x0A | RREP | 单播 | 1 | 路由应答 |
| 0x0B | RERR | 广播 | 1 | 路由失效 |
| 0x0C | PROFILE | 广播 | 3 | 能力/版本/频段画像协商 |

### 3.1 Payload 定义（CBOR map）

```text
BEACON   { n: nick, p: [lat,lon,alt], b: battery, c: caps, l: load, m: metrics, t: hlc }
SOS      { p: [lat,lon,alt], n: people, i: injury(0-3), m: note, b: battery, r: repeat }
TEXT     { ch: channelId, t: text, r: replyTo? }
POS      { p: [lat,lon,alt], a: accuracy, s: speed?, h: heading? }
POS_BATCH{ list: [[nodeId, lat, lon, alt, hlc], ...] }
VOICE_META{ ch, dur, codec, rate, chunks, size, sha }
VOICE_CHUNK{ id: voiceId, i: index, d: bytes }
ACK      { ack: msgId, st: status }
RREQ     { dst, seq, metric }
RREP     { src, dst, seq, route: [nodeId...], metric }
RERR     { dst, seq }
PROFILE  { v: protoVer, caps: [ble,wifi,lora,beidou,webrtc], band: regionProfile }
```

## 4. 邻居发现与链路度量

- BEACON 周期：基础 60 s，抖动 ±20%，拥塞时退避到 180 s。
- 邻居表项：`{nodeId, transport, rssi, snr, etx, lastSeen, battery, txPower, load, hops}`。
- 链路质量（越小越好）：

```
cost = w1 * (1 / clamp(snr, -20, 10)) + w2 * etx + w3 * (1 / battery) + w4 * load
默认 w = [0.4, 0.3, 0.2, 0.1]
```

- 邻居 3 个 BEACON 周期未更新 → 标记 stale；10 个周期 → 删除。

---

## 5. 中继选举（回答"自动选最优发射对象"）

**原则：不选"功率最高"，选"到目标最可靠且不拥塞"的节点。**

1. 每个节点根据邻居表计算到目的地的候选下一跳（单播）或覆盖得分（广播）。
2. 覆盖得分：

```
score = snr_norm * 0.35 + (1 - etx_norm) * 0.25 + altitude_norm * 0.15
      + battery_norm * 0.15 + (1 - load) * 0.10
```

3. **滞后防抖**：新候选得分需超过当前中继 20% 且持续 60 s 才切换；平局按 nodeId 字典序。
4. **禁止回环**：下一跳不能是上一跳；维护 `seenPath` 摘要。
5. 广播场景用"按得分排序的延迟转发"：得分越高延迟越短（0–200 ms），听到别人已转发则取消。

---

## 6. 广播抑制与去重

- 去重缓存键：`SRC + MSG_ID`，保留 10 min（或 1024 条上限，LRU）。
- 转发延迟：`delay = base + rank * step`，`base` 按优先级（SOS 0 ms，文字 80 ms）。
- TTL 默认：SOS 7，文字 5，位置 3，BEACON 1。
- 每节点空口预算：LoRa 每分钟 ≤ 30 s 发射（约 50% 占空比上限，按地区画像可调）。

---

## 7. 单播路由

- 有路由缓存 → 直接发。
- 无路由 → RREQ 洪泛（带目标、序号、累计度量），目标回 RREP；中间节点缓存反向路由。
- 路由 TTL 5 min；连续 3 次发送失败 → RERR 并清除。
- 兜底：路由失败时降级为"带目的地过滤的洪泛"。

---

## 8. 分片与重组

```
分片头: { fragId(4B), index(2B), total(2B), origType(1B) }
```

- 每传输层 MTU：LoRa 157 B，BLE 160 B，WiFi 1100 B。
- 重组超时 120 s；缺片可请求重传（NACK，最多 2 次）。
- 语音：Opus 16 kbps，每 20 ms 一帧 ≈ 40 B；按 4 帧/片打包。

---

## 9. 优先级与队列

| 优先级 | 内容 | 队列策略 |
|---|---|---|
| 0 | SOS | 抢占，立即发送，重发直到 ACK |
| 1 | ACK/路由控制 | 高，短队列 |
| 2 | 文字/语音 | 加权公平 |
| 3 | BEACON | 低，可延迟 |
| 4 | 位置批量/遥测 | 最低，可丢弃 |

## 10. 安全

### 10.1 身份

- 首次启动生成 Ed25519 密钥对；`nodeId = BLAKE2b(pubKey)[0..4]`。
- 加好友/入队：扫二维码交换公钥与昵称，本地建立信任。
- 身份消息（PROFILE、首次 SOS）用完整 Ed25519 签名；普通数据用群组 HMAC（省带宽）。

### 10.2 频道密钥

- 队伍频道：创建者生成 32 B 随机群密钥，通过 X25519 ECDH 封装后分发给成员。
- 公共频道：固定派生密钥（仅用于广播发现，不传敏感信息）。
- 轮换：成员变更时生成新密钥并广播密钥包（旧密钥保留 10 min 过渡）。

### 10.3 防重放与隐私

- HLC 单调 + 消息 ID 去重 + 时间窗（±10 min）。
- 公共频道位置模糊到 100 m 网格；精确位置仅加密频道。
- 可在设置中开启"隐身模式"（只收不发位置）。

## 11. 传输抽象层接口（TS 定义，多端共用）

```ts
export interface Envelope {
  version: 1;
  type: MessageType;
  flags: number;
  msgId: bigint;
  ttl: number;
  hop: number;
  src: number;
  dst: number;
  hlc: HLC;
  payload: Uint8Array; // CBOR
  auth: Uint8Array;    // HMAC 或签名
}

export interface TransportCapabilities {
  mtu: number;
  reliable: boolean;      // 是否可靠流（WiFi/WebRTC）
  broadcast: boolean;
  maxPeers: number;
  latencyMs: [number, number];
  costPerByte: number;    // 用于选路
}

export interface Transport {
  readonly kind: 'ble' | 'wifi' | 'lora' | 'beidou' | 'webrtc' | 'sim';
  readonly caps: TransportCapabilities;
  start(): Promise<void>;
  stop(): Promise<void>;
  send(frame: Uint8Array, peer?: NodeId): Promise<void>;
  onFrame(cb: (frame: Uint8Array, meta: LinkMeta) => void): void;
  peers(): PeerInfo[];
}

export interface MeshNode {
  readonly id: NodeId;
  onEnvelope(cb: (env: Envelope) => void): void;
  publish(type: MessageType, payload: unknown, opts?: SendOptions): Promise<void>;
  neighbors(): NeighborInfo[];
  routes(): RouteInfo[];
}
```

> 业务代码只依赖 `MeshNode`；`Transport` 由平台注入（Web 用 `sim`/`webrtc`，Android 用 `ble`+`lora`，桌面用 `lora` 串口）。

## 12. 仿真器设计（比赛演示核心）

- 节点：`{id, pos, battery, txPower, transport, role}`。
- 链路模型：对数距离路径损耗 + 随机阴影 + 移动模型（随机游走/沿道路）。
- 事件：节点上下线、分区、丢包率、拥塞。
- 可视化：地图上的节点、邻居连线（按 SNR 着色）、消息动画、路径高亮、中继选举标记。
- 指标：送达率、平均跳数、端到端时延、空口占用、电量消耗。
- 场景预设：城区 50 节点 / 山区 20 节点 / 灾区 100 节点 + 3 个中继。

## 13. 版本与兼容

- `VERSION` 主版本不同 → 拒绝并回 PROFILE 说明。
- 新增 TYPE 忽略未知类型（向前兼容）。
- payload 用 map，未知字段忽略。
- 设备画像（regionProfile）包含频段、功率、占空比，用于合规开关。
